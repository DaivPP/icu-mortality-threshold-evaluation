# Revisiting Clinical Severity Prediction: From Rule-Derived Labels to Real Outcomes

**Author:** Daivansh Pushkarna
**Date:** October 2026

## Abstract

An earlier capstone project (HEHCSP, 2025) trained a Random Forest classifier to predict
patient triage severity, reporting 99% accuracy. That result is misleading: the severity
labels were generated by deterministic rules applied to the same features used for
prediction, so the model was largely relearning the labeling rules rather than solving a
genuine predictive problem. This project repeats the exercise correctly — using real
in-hospital mortality outcomes from the MIMIC-IV Clinical Database Demo, proper
cross-validation, and threshold-aware evaluation suited to a rare, imbalanced outcome. The
central finding is modest and honest: early vital signs carry real but limited predictive
signal (PR-AUC ≈ 0.18–0.19 against an 11.7% base rate), and a transparent, un-fit threshold
rule is a surprisingly strong baseline that a Random Forest model only modestly improves
upon once thresholds are chosen fairly.

## 1. Motivation

My undergraduate capstone project (Hostile Environment Health Care Service Provider,
HEHCSP) included a machine-learning triage classifier that achieved 99% accuracy predicting
patient severity from physiological inputs. On inspection, this result does not demonstrate
what it appears to: the training labels were generated by deterministic clinical rules
(e.g. SpO₂ < 90% → Critical) applied directly to the same input features the model used for
prediction. A high-capacity classifier recovering a deterministic rule from its own inputs is
expected behavior, not evidence of clinical predictive ability.

This project asks the question properly: **can early vital signs predict a real clinical
outcome, evaluated honestly?**

## 2. Data

**Source:** MIMIC-IV Clinical Database Demo v2.2, accessed via the TinyEHR derivative
(open-licensed GitHub mirror matching the official PhysioNet demo schema and content).
The official demo is openly accessible on PhysioNet under the Open Data Commons license;
for any formal submission, the data should be obtained directly from PhysioNet
(physionet.org) to ensure correct provenance, with TinyEHR used here only as a
network-accessible mirror during development.

**Cohort:** All ICU stays in the 100-patient demo cohort, restricted to the first ICU stay
per hospital admission (to avoid correlated repeated-measures from the same
hospitalization). This yielded **128 admissions**.

**Label:** `hospital_expire_flag` from the admissions table — the actual recorded
in-hospital mortality outcome. **15 of 128 admissions (11.7%) ended in death.** This is a
real, moderately imbalanced outcome, not a researcher-defined rule.

**Features:** Summary statistics (mean, min, max) of five vital signs — heart rate,
systolic/diastolic blood pressure, respiratory rate, and SpO₂ — plus temperature (unified
from Celsius/Fahrenheit recordings) and patient age. All vitals were computed **only from
the first 24 hours of the ICU stay**, so no information from later in the stay (including
anything correlated with the eventual outcome) leaks into the features. Vital-sign coverage
was complete: all 128 stays had at least one recorded reading per vital in the window.

## 3. Methods

**Models compared:**
- A dummy classifier (always predicts survival) — the naive baseline.
- A transparent **threshold rule**, loosely modeled on early-warning scores such as qSOFA
  (SpO₂ < 92, systolic BP < 90, respiratory rate ≥ 22, heart rate > 110; flagged if ≥ 2
  criteria are met). This rule's thresholds were chosen from clinical convention, **not fit
  to this dataset** — it plays the role of an honest baseline to beat, not a source of
  labels.
- Logistic Regression (class-balanced).
- Random Forest (300 trees, max depth 5, class-balanced).

**Validation:** Given the small sample (N=128, 15 positive cases), a single train/test split
would produce a noisy, unreliable estimate. Models were evaluated using 5-fold stratified
cross-validation, **repeated 10 times with different random splits**, with metrics averaged
across repeats to give a more stable estimate and an explicit measure of variability.
Imputation and scaling were fit only on each fold's training data (via scikit-learn
`Pipeline`), to prevent information leakage from validation folds.

**Threshold handling:** An initial pass evaluated all models at the default 0.5 probability
threshold. This proved to be a poor and misleading comparison under 88/12 class imbalance
(see Results). A second pass instead tuned each model's decision threshold, via the
precision–recall curve, to match the rule baseline's recall (~80%) — allowing a fair,
apples-to-apples comparison of precision and F1 at a clinically meaningful, matched
sensitivity level. PR-AUC (average precision) is also reported as a threshold-independent
summary metric, which is more appropriate than ROC-AUC for rare-event prediction.

## 4. Results

### 4.1 Default threshold (0.5) — the naive comparison

| Model | Recall | Precision | F1 | ROC-AUC |
|---|---|---|---|---|
| Dummy (always survives) | 0.0% | — | — | — |
| Threshold rule (unfit) | 80.0% | 0.145 | 0.245 | — |
| Logistic Regression | 24.7% | — | — | 0.507 |
| Random Forest | 0.0% | — | — | 0.603 |

At the default threshold, both ML models perform *worse* than the simple rule, and Random
Forest misses every death despite a ROC-AUC (0.603) indicating it does rank risk better than
chance. This is a textbook consequence of class imbalance: `class_weight="balanced"`
reweights the training loss, but does not guarantee a well-calibrated 0.5 cutoff on
imbalanced data. Evaluating models only at the default threshold would have produced a
misleading conclusion ("ML doesn't work here") — this motivated the threshold-tuned
comparison below.

### 4.2 Threshold-tuned comparison — matched to ~80% recall

| Model | PR-AUC | Recall | Precision | F1 | Missed deaths (of 15) | False alarms |
|---|---|---|---|---|---|---|
| Threshold rule (unfit) | — | 80.0% | 0.145 | 0.245 | 3.0 | 71.0 |
| Logistic Regression | 0.194 ± 0.032 | 92.7% | 0.122 | 0.216 | 1.1 | 100.3 |
| **Random Forest** | 0.181 ± 0.050 | 85.3% | **0.159** | **0.268** | 2.2 | **68.9** |

Once thresholds are chosen fairly, Random Forest modestly outperforms the hand-specified
rule on precision and F1 at a comparable recall, with fewer false alarms. Logistic
Regression achieves the highest recall but at a steep precision cost. Both PR-AUC values
(0.18–0.19) are meaningfully above the 11.7% base rate, indicating real but modest
predictive signal — not a strong result, and reported as such.

### 4.3 Feature importance (Random Forest, fit on full data; for interpretation only)

Top contributing features: patient age, mean respiratory rate, mean temperature, minimum
heart rate, minimum diastolic BP, mean heart rate. No single vital sign dominates, which is
broadly consistent with early-24h deterioration being a multi-factorial signal rather than
driven by one threshold crossing — unlike the capstone's model, where SpO₂ alone carried
over a third of the total importance, a direct artifact of it being the dominant term in the
labeling rule itself.

## 5. Limitations

- **Sample size.** 128 admissions and 15 deaths is small; all metrics above are reported
  with their cross-repeat variability, and should be read as rough estimates, not precise
  performance figures. A single held-out test set was deliberately avoided in favor of
  repeated cross-validation, for exactly this reason.
- **Single demo cohort.** The MIMIC-IV *demo* is a 100-patient public subset of a single
  US academic medical center's data. No claims of generalization beyond this cohort are
  made.
- **No external validation.** Results are not validated against a separate dataset or
  population.
- **Feature scope.** Only vital signs and age were used; laboratory values, comorbidities,
  and clinical notes were not included and could materially change results.
- **Threshold-rule baseline.** The qSOFA-style rule's exact thresholds were chosen from
  general clinical convention and simplified for the features available here (e.g. omitting
  mentation status, which is part of true qSOFA); it is a reasonable baseline, not a
  validated clinical instrument as implemented here.

## 6. Relation to Future Work

This project deliberately stayed within a well-scoped, honestly-evaluated problem rather
than attempting a large or novel contribution. A natural next step — better suited to a
supervised research setting than a solo project — would be extending this evaluation
approach to **real hospital resource-utilization data**, in the spirit of nationwide
claims-data analyses of treatment resource usage. The methodological lessons here (label
provenance, threshold-aware evaluation under imbalance, honest reporting of modest effect
sizes) apply directly to that setting, where administrative and clinical data are similarly
imbalanced and similarly prone to misleading headline metrics if evaluated naively.

## 7. Conclusion

Early vital signs carry real, modest predictive signal for in-hospital mortality in this
cohort — not the near-perfect separability implied by the capstone's rule-derived labels,
but a genuine, if limited, signal that survives honest cross-validation and fair
threshold-matched comparison against a transparent clinical rule. The central
methodological lesson — that label provenance and threshold selection matter more than
model choice under class imbalance — is the main contribution of this exercise, and directly
addresses the flaw in the earlier project it revisits.
